# 유저는 무엇을 보고, 느끼고, 하는가

## 첫 방문

화면 전체가 지구본이다. 천천히 돌고 있다.
메뉴도 없다. 버튼도 없다. 지구본만 있다.

가운데에 두 줄:
```
C H A L D E A S
[시작하기]
```

시작하기를 누르면 지구본이 지중해로 날아간다. 480 BCE.
마커들이 하나둘 떠오른다. 아래쪽에 타임라인 바가 나타난다.

이게 전부다. 유저는 이제 탐험할 준비가 되었다.

---

## 탐험의 두 가지 길

### 길 1: 지구본을 만지는 사람 (Explorer)

지구본을 돌린다 → 마커가 보인다 → 누른다 → 이야기가 열린다.

지구본을 확대한다 → 마커가 바뀐다 → 더 자세한 이야기가 보인다.

타임라인을 움직인다 → 마커가 바뀐다 → 다른 시대의 이야기가 보인다.

**느낌**: "이 시대에 이 지역에서 이런 일이 있었구나. 저쪽은 뭘까?"

### 길 2: 읽는 것을 좋아하는 사람 (Reader)

타임라인에서 시대를 누른다 → 시대 개요가 열린다 → 지역별/주제별 목록이 보인다 → 아무거나 누르면 지구본이 그곳으로 날아간다.

또는: 가이드 투어를 선택한다 → "그리스-페르시아 전쟁" 7단계를 따라간다 → 각 단계마다 지구본이 자동으로 이동한다.

**느낌**: "책처럼 순서대로 읽을 수도 있네. 근데 지구본에서 실제 위치가 보이니까 다르다."

---

## 순간순간의 경험

### 마커를 누르면

오른쪽에서 카드가 스르륵 나온다.

```
┌─────────────────────────────┐
│ Battle of Thermopylae       │
│ 480 BCE · Thermopylae       │
│                             │
│ 레오니다스 1세가 300명의    │
│ 스파르타 병사와 함께        │
│ 크세르크세스의 대군을       │
│ 3일간 저지했다.             │
│                             │
│ 원인 ← Marathon (490 BCE)   │
│ 결과 → Salamis (480 BCE)    │
│                             │
│ 참여 인물:                  │
│  Leonidas I · Xerxes I      │
│                             │
│ 확실성: fact                │
│ 출처: Herodotus, Histories  │
└─────────────────────────────┘
```

카드 안에서 "Leonidas I"를 누르면 → 인물 카드로 전환된다.
"원인 ← Marathon"을 누르면 → 지구본이 마라톤 평원으로 날아간다.

**핵심**: 카드 안의 모든 것은 누를 수 있다. 누르면 지구본이 반응한다.

### 인물을 누르면

```
┌─────────────────────────────┐
│ Leonidas I                  │
│ King of Sparta              │
│ 540 BCE — 480 BCE           │
│                             │
│ 생애:                       │
│  540 Sparta (출생)          │
│   ↓                         │
│  490 Sparta (왕위 계승)     │
│   ↓                         │
│  480 Thermopylae (최후)     │
│                             │
│ 관계:                       │
│  Gorgo (아내)               │
│  Xerxes I (적)              │
│  Themistocles (동맹)        │
│                             │
│ 도메인: military            │
│ 확실성: fact                │
└─────────────────────────────┘
```

생애의 각 단계를 누르면 → 지구본이 그 장소로 날아간다.
관계의 인물을 누르면 → 그 인물의 카드로 전환된다.

**핵심**: 인물은 데이터베이스의 항목이 아니다. 지구본 위에서 살았던 사람이다.
생애의 각 단계는 공간 위의 점이다.

### 장소를 누르면

```
┌─────────────────────────────┐
│ Constantinople               │
│ (현재: Istanbul)             │
│                             │
│ 이름의 역사:                │
│  Byzantium (667 BCE~330)    │
│  → Constantinople (330~1930)│
│  → Istanbul (1930~)         │
│                             │
│ 소속:                       │
│  로마 제국 (330~395)        │
│  동로마 제국 (395~1453)     │
│  오스만 제국 (1453~1922)    │
│  터키 공화국 (1923~)        │
│                             │
│ 이곳의 사건들: (12)         │
│  330  로마 수도 이전        │
│  532  니카의 반란           │
│  1204 제4차 십자군 약탈     │
│  1453 콘스탄티노플 함락     │
└─────────────────────────────┘
```

**핵심**: 장소는 고정된 좌표다. 하지만 이름은 바뀌고, 주인은 바뀌고, 사건은 쌓인다.
같은 점 위에 수천 년의 이야기가 층층이 쌓여있다.
타임라인을 움직이면 이 장소의 이름이 바뀐다.

## 시간을 움직이면 무슨 일이 일어나는가

타임라인 바를 480 BCE에서 400 BCE로 드래그한다.

**지구본 위에서 벌어지는 일:**
1. 테르모필레, 살라미스 마커가 희미해진다 (이제 과거의 일)
2. 아테네 주변에 새 마커가 떠오른다: "펠로폰네소스 전쟁", "페리클레스 시대"
3. 페르시아 영토가 서서히 줄어든다 (영토 오버레이)
4. 소크라테스, 페리클레스 아이콘이 나타난다
5. 장소 이름이 변한다 (해당되는 경우)

**유저가 느끼는 것:**
"시간이 흐르니까 세계가 변했다. 전쟁이 끝나고 철학의 시대가 왔구나."

이것이 책이나 위키피디아로는 절대 줄 수 없는 경험이다.
**시간의 흐름 속에서 세계 전체가 변하는 것을 한눈에 보는 것.**

## 2-탭 규칙

어떤 콘텐츠든 최대 2번 터치로 도달할 수 있어야 한다.

| 보고 싶은 것 | 1탭 | 2탭 |
|-------------|-----|-----|
| 특정 사건 | 지구본에서 마커 클릭 | (바로 보임) |
| 특정 인물 | 사이드바 People 탭 | 인물 카드 클릭 |
| 특정 시대 | 타임라인 시대 라벨 클릭 | (바로 보임) |
| 가이드 투어 | 투어 카드 클릭 | 시작 버튼 |
| 특정 도메인 | People 탭 도메인 선택 | 인물 카드 클릭 |

3탭 이상이 필요하면 설계가 잘못된 것이다.

## 기본 상태

앱을 열면 보이는 것:
- 지구본 (화면 대부분)
- 타임라인 바 (하단)
- 최소한의 사이드바 또는 진입점

**보이지 않는 것:**
- 풀스크린 모달
- 여러 겹의 탭
- "무엇을 해야 하지?"라는 고민

유저는 **지구본을 보고 있다.** 그것이 기본 상태다.

## 설계 원칙 (사용자 피드백 반영)

### 원칙 1: 랜딩은 1회성이 아니다

"시작하기"는 처음뿐이다. 하지만 그 아래의 세계는 항상 접근 가능해야 한다.

- localStorage 플래그로 랜딩을 숨기는 것은 결함이다
- "홈 화면" = 글로브 + "지금 볼 만한 것" 추천
- 언제든 돌아올 수 있는 시작점이어야 한다
- 첫 방문자에게는 "시작하기" 버튼이, 재방문자에게는 추천 콘텐츠가 보인다

### 원칙 2: ViewportFeed는 상시 컨텍스트

글로브 옆에 **항상** 보이는 "지금 보이는 것" 패널이 있다.

- 글로브를 돌리면 자동으로 업데이트된다
- 현재 뷰포트 안의 이벤트/인물을 중요도순으로 보여준다
- 사이드바(서랍)의 FeedTab과는 다르다: ViewportFeed는 글로브의 동반자
- 글로브와 1:1로 묶여있어서, 글로브가 보이면 ViewportFeed도 보인다

### 원칙 3: 모드 분리 없음

Interest/Expert 같은 모드 전환은 없다.

- 줌 레벨이 자연스럽게 서사 해상도를 결정한다
- 사용자가 "모드"를 선택하는 것이 아니라 글로브 인터랙션이 경험을 결정한다
- 멀리서 보면 큰 그림, 가까이 가면 세부 정보 — 이것이 모드를 대체한다
- 명시적 토글은 인지 부하만 만든다

### 원칙 4: 글로브 회전 속도 ≠ 시간 이동 속도

두 개의 독립적인 제어가 있다.

- 글로브를 빠르게 돌리면서 시간은 천천히 갈 수 있다
- 시간을 빠르게 넘기면서 같은 장소를 계속 볼 수 있다
- 타임라인 재생 속도와 글로브 회전은 서로 간섭하지 않는다
- 이것이 "시간여행"을 진짜 시간여행처럼 만드는 핵심이다

### 원칙 5: 백엔드 기능 전부 노출

백엔드에 있는 모든 기능은 프론트엔드에서 접근 가능해야 한다.

- 기능 삭제 = 퇴행
- 새 디자인에 맞게 **재배치**하되, **없애지** 않는다
- Person flow, relations, sources, properties — 모두 어딘가에서 보여야 한다
- API가 존재하면 UI도 존재해야 한다
- "아직 UI가 없다"는 허용되지만, "있던 UI를 없앴다"는 허용되지 않는다
