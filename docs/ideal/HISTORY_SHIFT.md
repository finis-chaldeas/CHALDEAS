# 히스토리 시프트 (History Shift)

**에이지 오브 엠파이어의 시나리오를 지구본 위에서.**

---

## 1장. 히스토리 시프트란?

### 정의

히스토리 시프트는 **연속된 사건들을 처음부터 끝까지 보여주는 시나리오 단위**다.

에이지 오브 엠파이어 2-3의 시나리오 모드를 떠올려라.
"잔 다르크" 시나리오를 선택하면, 첫 번째 미션부터 마지막 미션까지
순서대로 이야기가 펼쳐진다. 각 미션은 다른 맵에서 일어나고,
이전 미션의 결과가 다음 미션의 배경이 된다.

FGO의 특이점/이문대도 같은 구조다.
"바빌로니아"를 선택하면 1장부터 22장까지 순서대로 진행되고,
각 장은 다른 장소에서 다른 사건이 일어난다.

히스토리 시프트는 이 경험을 **실제 역사**로 옮긴 것이다.
"그리스-페르시아 전쟁"을 선택하면, 이오니아 반란부터 플라타이아 전투까지
지구본이 자동으로 이동하면서 이야기가 펼쳐진다.

### 기존 시스템과의 관계

지금까지 비슷한 목적으로 여러 시스템이 병렬 개발되었다.
히스토리 시프트는 이들을 하나로 통합한다.

| 기존 시스템 | 역할 | → 히스토리 시프트에서 |
|------------|------|----------------------|
| ~~Rayshift~~ | 순차 탐색 UI | 시프트의 **네비게이션 모드** (페이지 이동 엔진) |
| ~~Histories~~ | 에세이 콘텐츠 | 시프트의 **에세이형 콘텐츠** (페이지 내러티브) |
| ~~Historical Chain~~ | 데이터 모델 | 시프트의 **데이터 모델** (리네이밍 + 확장) |
| ~~Event Hierarchy~~ | 부모-자식 구조 | 시프트의 **챕터/중첩 구조** (자동 시프트 생성 소스) |

**기존 시스템은 삭제되지 않는다.**
데이터 테이블(`event_parents`, `event_connections`)은 그대로 유지되며,
히스토리 시프트를 자동 생성할 때 입력 소스로 활용된다.

### 5가지 유형

| 유형 | chain_type | 설명 | 예시 |
|------|-----------|------|------|
| **인물 이야기** | `person_story` | 한 인물의 생애를 따라감 | 알렉산더의 일생, 잔 다르크의 여정 |
| **장소 이야기** | `place_story` | 한 장소의 시간을 따라감 | 이스탄불 3000년, 로마의 흥망 |
| **시대 이야기** | `era_story` | 한 시대의 인물/사건/장소 종합 | 르네상스, 전국시대, 대항해시대 |
| **인과 사슬** | `causal_chain` | 원인→결과로 이어지는 사건 흐름 | 마라톤→테르모필레→살라미스→플라타이아 |
| **대사건** | `aggregate` | 하위 사건을 포함하는 큰 사건 | 백년전쟁, 산업혁명, 그리스-페르시아 전쟁 |

처음 4개는 기존 HistoricalChain의 `chain_type`과 동일하다.
5번째 `aggregate`는 기존 `events.is_aggregate=true` 이벤트를 시프트로 승격시킨 것이다.

## 2장. UI — 전용 모달 페이지

### 핵심 결정: 전체화면 모달

히스토리 시프트는 **전체화면 모달**로 표시된다.
글로브 위에 오버레이되며, 거의 전체 화면을 차지한다.

왜 전체화면인가?
- 기존 Rayshift는 하단 오버레이였다. 너무 작았다.
- 시프트는 이야기를 **몰입해서 읽는** 경험이다.
- 에이지 오브 엠파이어의 시나리오 브리핑도 전체화면이다.
- 글로브는 배경으로 보이지만, 주인공은 이야기다.

### 페이지 이동

- **하단 썸네일 바**: 모든 페이지가 번호로 표시. 현재 페이지만 하이라이트.
- **좌우 스와이프** (모바일): 이전/다음 페이지.
- **← 이전 / 다음 →** 버튼: 데스크톱에서 클릭.
- **키보드**: ← → 화살표 키로 이동.
- **썸네일 클릭**: 원하는 페이지로 점프.

### 챕터 분류

큰 시프트는 **챕터**로 나뉜다.

```
백년전쟁 (전체 시프트)
  ├── 1장: 에드워드 3세의 도전 (1337-1360)
  │     ├── 페이지 1: 왕위 계승 분쟁
  │     ├── 페이지 2: 크레시 전투
  │     └── 페이지 3: 푸아티에 전투
  ├── 2장: 프랑스의 반격 (1360-1415)
  │     ├── 페이지 4: 뒤게클랭의 활약
  │     └── 페이지 5: 프랑스의 혼란
  ├── 3장: 아쟁쿠르와 잔 다르크 (1415-1453)
  │     ├── 페이지 6: 아쟁쿠르 전투
  │     ├── 페이지 7: 잔 다르크의 등장
  │     ├── 페이지 8: 오를레앙 해방
  │     └── 페이지 9: 잔 다르크의 최후
  └── 4장: 전쟁의 끝 (1453)
        └── 페이지 10: 카스티용 전투
```

- **챕터 드롭다운**: 상단 우측의 `[챕터 ▼]`을 클릭하면 챕터 목록이 나온다.
- 챕터를 선택하면 해당 챕터의 첫 페이지로 점프.
- 하단 썸네일 바에서 챕터 경계는 시각적으로 구분 (구분선 또는 색상).

### 중첩 (Sub-Shift)

시프트 안에서 **하위 시프트**를 열 수 있다.

```
[백년전쟁 시프트] → 페이지 7: "잔 다르크의 등장"
  → [잔 다르크 보기] 버튼 클릭
  → 잔 다르크의 인물 시프트가 열림
  → 브레드크럼: 백년전쟁 > 잔 다르크
  → 잔 다르크 시프트를 닫으면 → 백년전쟁 페이지 7로 복귀
```

이것은 에이지 오브 엠파이어의 "역사 정보" 팝업과 같다.
시나리오 미션 중에 인물이나 장소에 대한 추가 정보를 열어볼 수 있고,
닫으면 원래 미션으로 돌아온다.

**브레드크럼 표시**:
```
백년전쟁 > 잔 다르크 > 오를레앙 공방전
```
깊이 제한은 3단계까지.

### 글로브 연동

시프트 모달은 배경 글로브와 **실시간 연동**된다.

1. **페이지 이동 시**: 배경 글로브가 해당 이벤트의 위치/시대로 자동 이동.
   - 마라톤 → 테르모필레 → 살라미스: 글로브가 순서대로 날아감.
2. **투명도 조절**: 모달 투명도를 낮추면 배경 글로브를 더 크게 볼 수 있음.
   - 슬라이더 또는 "글로브 보기" 토글.
3. **미니맵**: 페이지 내 지도 미니뷰에 현재 위치 표시.
   - 미니맵 클릭 → 모달을 최소화하고 글로브에서 해당 위치 탐색 가능.

## 3장. 글로브 표시

### 히어로 카드

중요 시프트는 글로브 위에 **히어로 카드**로 표시된다.

```
┌──────────────────┐
│ ⚔ 그리스-페르시아 │
│    전쟁            │
│ 499-449 BCE       │
└──────────────────┘
```

- **아이콘**: 시프트 유형을 나타냄
  - 📖 시대 이야기 (era_story)
  - ⚔ 인과 사슬 / 대사건 (causal_chain, aggregate)
  - 👤 인물 이야기 (person_story)
  - 📍 장소 이야기 (place_story)
- **클릭**: 시프트 모달이 열림.
- **위치**: 시프트의 대표 좌표 (focal entity의 위치).
- **기존 smart markers와의 관계**: 히어로 카드는 smart markers의 한 유형이다.
  기존 이벤트/인물 마커와 충돌하지 않으며, 별도의 레이어로 렌더링.

### 경로 아크

시프트의 이벤트 경로를 글로브 위에 **곡선 아크**로 표시한다.

```
알렉산더의 여정:
  펠라 ──→ 그라니코스 ──→ 이소스 ──→ 가우가멜라 ──→ 바빌론
  (파랑)    (파랑-초록)    (초록)     (노랑-주황)     (빨강)
```

- **색상 그라데이션**: 시작=파랑(#3B82F6) → 끝=빨강(#EF4444). 시간순.
- **선 두께**: importance에 비례. 중요한 시프트일수록 굵게.
- **애니메이션**: 시프트 모달이 열리면, 아크가 시작점부터 순차적으로 그려짐.
- **호버**: 아크 위에 마우스를 올리면 시프트 제목 + 기간 표시.

### 표시 조건

줌 레벨과 `globe_importance`에 따라 표시되는 시프트가 달라진다.

| 줌 레벨 | globe_importance | 표시되는 시프트 | 예시 |
|---------|-----------------|---------------|------|
| COSMIC | 5 | 문명급 시프트만 | 로마제국의 흥망, 이슬람 확장 |
| CONTINENTAL | 4+ | 전쟁/왕조급 추가 | 백년전쟁, 몽골 원정, 십자군 |
| REGIONAL | 3+ | 인물/전투급 추가 | 잔 다르크, 살라미스 해전 |
| LOCAL | 2+ | 소규모 시프트 추가 | 특정 전투의 날별 전개 |

이 규칙은 기존 줌 = 서사 해상도 원칙과 정확히 일치한다.
`ZOOM_AS_NARRATIVE.md`에서 정의한 것과 같이,
줌아웃하면 큰 이야기가, 줌인하면 작은 이야기가 보인다.

## 4장. 데이터 모델

### 기존 모델 확장

기존 `HistoricalChain` 모델을 `HistoryShift`로 리네이밍하고 필드를 확장한다.

#### HistoryShift (← HistoricalChain)

기존 필드는 모두 유지하며, 다음 필드를 추가:

```python
# === 기존 필드 (유지) ===
id, chain_type, slug, title, title_ko,
summary, summary_ko,
focal_person_id, focal_location_id, focal_period_id, focal_event_id,
year_start, year_end, temporal_scale, region,
segment_count, entity_count,
status, access_count, last_accessed_at,
is_auto_generated, generation_model, generation_prompt_hash,
quality_score, human_reviewed,
created_by_master_id, created_at, updated_at

# === 추가 필드 ===
display_type       # 'modal' | 'inline'  (전체화면 vs 인라인)
chapter_count      # int                 (챕터 수)
globe_importance   # int (1-5)           (글로브 표시 우선순위)
thumbnail_url      # string              (히어로 카드 썸네일)
parent_shift_id    # FK (self)           (중첩 시프트 — 부모 시프트 참조)
```

| 새 필드 | 타입 | 설명 |
|--------|------|------|
| `display_type` | `String(10)` | `'modal'`: 전체화면 모달, `'inline'`: 인라인 표시 |
| `chapter_count` | `Integer` | 시프트 내 챕터 수. 단일 챕터면 1 |
| `globe_importance` | `Integer` | 1-5. 글로브 위 표시 우선순위. 5=문명급, 1=소규모 |
| `thumbnail_url` | `String(500)` | 히어로 카드에 표시할 이미지 URL |
| `parent_shift_id` | `Integer FK` | 부모 시프트 ID. 중첩 시프트일 때 사용 |

또한, `chain_type`에 `'aggregate'` 값을 추가:
```python
chain_type: 'person_story' | 'place_story' | 'era_story' | 'causal_chain' | 'aggregate'
```

#### ShiftPage (← ChainSegment)

기존 필드는 모두 유지하며, 다음 필드를 추가:

```python
# === 기존 필드 (유지) ===
id, chain_id (→ shift_id로 리네이밍), sequence_number,
title, narrative, narrative_ko,
event_id, person_id, location_id, period_id,
year_start, year_end, temporal_scale,
transition_type, transition_strength, transition_narrative,
importance, is_keystone, created_at

# === 추가 필드 ===
chapter_title      # string              (소속 챕터 제목)
chapter_number     # int                 (챕터 번호, 1-indexed)
page_narrative     # text                (페이지별 상세 내러티브)
page_narrative_ko  # text                (한국어)
sub_shift_id       # FK (history_shifts) (이 페이지에서 열 수 있는 하위 시프트)
media_url          # string              (이미지/지도 URL)
```

| 새 필드 | 타입 | 설명 |
|--------|------|------|
| `chapter_title` | `String(200)` | 소속 챕터 제목. "에드워드 3세의 도전" |
| `chapter_number` | `Integer` | 챕터 번호 (1부터 시작) |
| `page_narrative` | `Text` | 기존 `narrative`보다 긴 상세 내러티브. 모달에서 보여줄 본문 |
| `page_narrative_ko` | `Text` | 한국어 상세 내러티브 |
| `sub_shift_id` | `Integer FK` | 이 페이지에서 [하위 시프트 보기] 버튼을 눌렀을 때 열릴 시프트 |
| `media_url` | `String(500)` | 페이지에 표시할 이미지 또는 지도 이미지 URL |

#### ChainEntityRole — 변경 없음

기존 `ChainEntityRole`은 그대로 유지. 테이블명도 유지.
시프트 내에서 인물/장소/이벤트의 역할 (protagonist, antagonist 등)을
추적하는 데 이미 충분하다.

### 마이그레이션 계획

```
# 테이블 리네이밍
historical_chains  →  history_shifts
chain_segments     →  shift_pages

# FK 리네이밍
chain_segments.chain_id  →  shift_pages.shift_id
chain_entity_roles.chain_id  →  chain_entity_roles.shift_id

# 새 컬럼 추가 (ALTER TABLE)
history_shifts: display_type, chapter_count, globe_importance,
                thumbnail_url, parent_shift_id
shift_pages:    chapter_title, chapter_number, page_narrative,
                page_narrative_ko, sub_shift_id, media_url
```

## 5장. 콘텐츠 생성 파이프라인

### Phase 1: 대사건 자동 시드 (aggregate → 시프트)

**대상**: `is_aggregate=true` 이벤트 121개.

```
입력: events WHERE is_aggregate=true
  └─ 각 aggregate의 children (event_parents.parent_event_id)
      └─ children을 year_start 순 정렬

출력: history_shifts (chain_type='aggregate')
  └─ shift_pages (각 child event = 1 페이지)
```

**LLM 작업** (gpt-5-mini):
1. 각 페이지의 `page_narrative` 생성 (3-5문장, 해당 이벤트의 이야기)
2. 페이지 간 `transition_narrative` 생성 ("이 전투 이후..." 같은 연결 텍스트)
3. 챕터 분류 제안 (10페이지 이상이면 3-4개 챕터로 분할)

**예상 비용**: 121개 시프트 × 평균 8페이지 × ~500토큰 = ~$1.2

### Phase 2: 인물/장소 시프트

**인물 시프트** (person_story):
```
대상: persons WHERE importance >= 4 (약 200명)
입력: /persons/{id}/flow (생애 이벤트 체인)
출력: history_shifts (chain_type='person_story')
  └─ shift_pages (각 flow 항목 = 1 페이지)
```

**장소 시프트** (place_story):
```
대상: locations WHERE importance >= 4 (주요 도시/장소)
입력: 해당 location의 events (시간순)
출력: history_shifts (chain_type='place_story')
  └─ shift_pages (주요 이벤트 선별 = 페이지)
```

**LLM 작업** (gpt-5-mini):
1. 인물: 생애 내러티브 (탄생 → 업적 → 사망)
2. 장소: 시대별 변천 내러티브 (건설 → 전성기 → 변화)
3. 챕터 분류 (시기별로 나눔)

**예상 비용**: ~200 인물 + ~100 장소 × 평균 10페이지 × ~500토큰 = ~$3.8

### Phase 3: 인과 사슬 시프트

**대상**: `event_connections` WHERE `layer_type='causal'`.

```
입력: event_connections (causal 관계)
  └─ 그래프 순회: 시작 이벤트에서 causal 엣지를 따라 체인 추출
  └─ 체인 길이 3 이상만 시프트 생성

출력: history_shifts (chain_type='causal_chain')
  └─ shift_pages (체인의 각 이벤트 = 1 페이지)
```

**LLM 작업** (gpt-5-mini):
1. 인과 내러티브 ("이 사건이 일어난 이유는...")
2. 전환 텍스트 ("그 결과로...")
3. 전체 체인의 summary (왜 이 인과관계가 중요한가)

**예상 비용**: ~50 체인 × 평균 5페이지 × ~500토큰 = ~$0.3

### 전체 비용 요약

| Phase | 시프트 수 | 비용 |
|-------|----------|------|
| Phase 1: 대사건 | ~121 | ~$1.2 |
| Phase 2: 인물/장소 | ~300 | ~$3.8 |
| Phase 3: 인과 사슬 | ~50 | ~$0.3 |
| **합계** | **~471** | **~$5.3** |

### 검수 워크플로우

```

  ↓

  ↓
quality_score < 0.7 → 재생성 또는 수동 편집 대상
quality_score >= 0.7 → 검수 대기열
  ↓
사람 검수:
  - 이벤트 순서 정확한가?
  - 빠진 이벤트가 없는가?

  ↓
```

### NarrativePanel과의 관계

NarrativePanel은 **개별 이벤트/인물의 상세 정보**를 보여준다.
히스토리 시프트는 **연속된 이벤트의 이야기**를 보여준다.

둘은 별개의 UI이며, 서로를 연결한다:

```
NarrativePanel (이벤트 상세)
  └─ "이 사건의 시프트 보기" → 시프트 모달 열림

시프트 모달 (페이지 탐색)
  └─ 이벤트 제목 클릭 → NarrativePanel 열림 (모달 뒤에)
```

# 히스토리 시프트 — 보강 기획 (V2)

**위의 기초 기획 위에 쌓는 디자인 심화.**

위 기획은 "데이터 구조를 짜고, 자동 시드로 최소한의 페이지를 만들어 UI를 검증한다"에 초점을 맞추었다.
이 보강 기획은 **실제 사용자에게 보여줄 최종 경험**을 정의한다.

핵심 문제의식:
- 현재 시프트 페이지는 텍스트 나열에 불과하다. 히어로 카드 우측 패널과 다를 바 없다.
- 전쟁 이야기만 넣을 게 아니다. 문화 흐름, 철학사, 과학 혁명, 종교 전파도 시프트의 대상이다.
- LLM 자동 생성 텍스트는 **임시 폴백**일 뿐이다. 최종 콘텐츠는 사람이 큐레이션하고 AI가 다듬는다.
- 각 페이지는 콘텐츠 유형에 맞는 **전용 카드 레이아웃**을 가져야 한다.

---

## 7장. 리치 카드 시스템

### 원칙: "신문 1면처럼"

시프트 페이지 하나하나가 **잡지 한 페이지** 같아야 한다.
텍스트만 나열하면 위키피디아다. 우리는 내셔널 지오그래픽이다.

각 페이지는:
1. **한 눈에 잡히는 비주얼** — 이미지, 지도, 다이어그램, 진영 배치
2. **3초 안에 파악되는 핵심** — 제목 + 연도 + 위치 + 한 줄 요약
3. **몰입할 수 있는 내러티브** — 교과서가 아니라 이야기
4. **콘텐츠 유형에 맞는 구조** — 전투엔 전투 카드, 인물엔 인물 카드

### 페이지 카드 공통 구조

모든 페이지 카드는 아래 공통 레이아웃을 공유한다:

```
┌──────────────────────────────────────────────────┐
│  [ 카드 유형 뱃지 ]          480 BCE · 살라미스    │  ← 메타 라인
├──────────────────────────────────────────────────┤
│                                                   │
│              [ 유형별 비주얼 영역 ]                │  ← 카드마다 다름
│                                                   │
├──────────────────────────────────────────────────┤
│                                                   │
│  살라미스 해전                                     │  ← 제목
│  Battle of Salamis                                │  ← 원어 제목
│                                                   │
│  좁은 해협에 페르시아 함대를 끌어들인              │  ← 내러티브
│  테미스토클레스의 전략은...                         │
│                                                   │
├──────────────────────────────────────────────────┤
│  📚 출처: Herodotus, Histories VIII              │  ← 출처 (있을 때만)
│  🔗 관련: 테르모필레 전투 · 플라타이아 전투       │  ← 관련 링크
└──────────────────────────────────────────────────┘
```

**공통 필드**:
- 메타 라인: 카드 유형 뱃지, 연도, 위치
- 제목: 한국어 + 원어
- 내러티브: `page_narrative` (큐레이션 버전) 또는 `narrative` (자동생성 폴백)
- 출처: 연결된 `academic_papers` / `text_mentions` (있을 때만 표시)
- 관련 링크: 이전/다음 이벤트, 관련 인물, 관련 시프트

```
│                                                   │
│  보스포루스 해협의 이 도시는 로마, 비잔틴,          │
│  오스만 세 제국의 수도였다. 콘스탄티누스가          │
│  이곳을 "새 로마"로 선언한 이후...                  │
│                                                   │
└──────────────────────────────────────────────────┘
```

**비주얼 영역 구성**:
- 지도 미니뷰 또는 위성/유적 이미지
- 이름 변천 타임라인 (시간에 따른 이름 변화)
- 해당 시기의 이름 강조

### 8-4. 문화·사상 카드 (Cultural/Intellectual Card)

**적용 조건**: `event.event_type IN ('cultural', 'intellectual', 'religious', 'scientific')` 또는 수동 지정

```
┌──────────────────────────────────────────────────┐
│  💡 사상          5C BCE · 아테네                  │
├──────────────────────────────────────────────────┤
│                                                   │
│   ┌──────────────────────────────────────────┐   │
│   │                                          │   │
│   │  계보도 / 영향 다이어그램               │   │
│   │                                          │   │
│   │  탈레스 → 아낙시만드로스 → 아낙시메네스  │   │
│   │              ↓                           │   │
│   │          피타고라스 → 파르메니데스        │   │
│   │              ↓              ↓            │   │
│   │          소크라테스 → 플라톤 → 아리스토텔레스 │
│   │                                          │   │
│   └──────────────────────────────────────────┘   │
│                                                   │
│   핵심 사상: 자연철학 → 윤리학 → 형이상학         │
│   핵심 물음: "만물의 근원은 무엇인가?"             │
│                                                   │
├──────────────────────────────────────────────────┤
│                                                   │
│  밀레토스에서 아테네까지: 그리스 철학의 여정       │
│                                                   │
│  탈레스가 "만물은 물이다"라고 선언한 순간,         │
│  인류는 신화가 아닌 이성으로 세계를 설명하기       │
│  시작했다. 이오니아 자연철학은 아테네로 흘러가      │
│  소크라테스의 윤리학, 플라톤의 이데아론,           │
│  아리스토텔레스의 체계적 학문으로 꽃피었다.        │
│                                                   │
├──────────────────────────────────────────────────┤
│  📚 Diogenes Laërtius, Lives of Eminent Phil.    │
│  🔗 소크라테스 · 플라톤 · 아리스토텔레스          │
└──────────────────────────────────────────────────┘
```

**비주얼 영역 구성**:
- 계보도 / 영향 관계 다이어그램 (인물 간 사승 관계)
- 핵심 사상/물음 요약 (키워드형)
- 전파 경로 (지역 이동을 보여주는 화살표)

### 8-5. 전환 카드 (Transition Card)

**적용 조건**: 챕터 전환 시점, 또는 `transition_type IN ('causes', 'consequence', 'enables')`이면서 시간 간극이 클 때

시프트 내에서 챕터가 바뀌거나 큰 시간 점프가 있을 때 삽입되는 특수 카드.

```
┌──────────────────────────────────────────────────┐
│                                                   │
│              ─── 2장 ───                          │
│        프랑스의 반격 (1360-1415)                   │
│                                                   │
│   크레시와 푸아티에의 패배 이후 55년,              │
│   프랑스는 뒤게클랭의 지휘 아래 잃은 땅을          │
│   하나씩 되찾기 시작한다.                          │
│                                                   │
│              ─── ⏳ ───                            │
│                                                   │
└──────────────────────────────────────────────────┘
```

텍스트 중심, 비주얼 최소. 챕터의 맥락을 짧게 설정하는 역할.

### 8-6. 일반 카드 (Generic Card)

**적용 조건**: 위 유형에 해당하지 않는 경우 (기본값)

1장 기초 기획의 페이지 구조를 그대로 따른다 — 제목, 연도, 위치, 내러티브, 이미지(있으면).

### 카드 유형 자동 선택 로직

```
if page.event and page.event.event_type in ('battle', 'siege'):
    → BattleCard
elif page.person_id or chain_type == 'person_story':
    → PersonCard
elif page.location_id or chain_type == 'place_story':
    → PlaceCard
elif page.event and page.event.event_type in ('cultural', 'intellectual', 'religious', 'scientific'):
    → CulturalCard
elif page.is_chapter_transition:
    → TransitionCard
else:
    → GenericCard
```

프론트엔드에서 판별하며, 백엔드는 필요한 데이터만 제공한다.
잘못된 자동 선택은 `chain_segments`에 `card_type_override` 필드를 추가해서 수동 보정 가능.

## 9장. 전쟁 너머 — 다양한 시프트 콘텐츠

시프트는 전쟁 이야기만을 위한 시스템이 아니다.
역사의 모든 흐름 — 문화, 사상, 과학, 종교, 경제 — 이 시프트의 대상이다.

### 9-1. 문화 흐름 시프트

**예시**: "르네상스의 확산" (14C 이탈리아 → 16C 북유럽)

```
페이지 1: 피렌체 — 메디치 가문의 후원 (1400년대)
페이지 2: 브루넬레스키의 두오모 (건축)
페이지 3: 보티첼리와 레오나르도 (미술)
페이지 4: 마키아벨리 (정치 사상)
페이지 5: 베네치아로의 확산 (티치아노)
페이지 6: 뒤러와 북유럽 르네상스 (뉘른베르크)
페이지 7: 에라스뮈스 (네덜란드 인문주의)
페이지 8: 셰익스피어 (영국 르네상스)
```

글로브가 피렌체에서 시작해서 베네치아 → 뉘른베르크 → 로테르담 → 런던으로 이동.
문화가 지리적으로 전파되는 과정을 **지구본 위에서 체감**한다.

카드 유형: CulturalCard (계보도 + 영향 관계) + PersonCard (개별 인물) + PlaceCard (도시)

### 9-2. 철학사 시프트

**예시**: "고대 그리스 철학" (6C BCE 밀레토스 → 3C BCE 아테네)

```
페이지 1: 밀레토스 — 탈레스, 최초의 철학자 (6C BCE)
페이지 2: 피타고라스와 크로톤 학파 (6C BCE)
페이지 3: 헤라클레이토스 vs 파르메니데스 (5C BCE)
페이지 4: 아테네 — 소크라테스의 등장 (5C BCE)
페이지 5: 플라톤과 아카데메이아 (4C BCE)
페이지 6: 아리스토텔레스와 리케이온 (4C BCE)
페이지 7: 스토아학파와 에피쿠로스학파 (3C BCE)
페이지 8: 알렉산드리아의 학문 전통 (3C-1C BCE)
```

글로브가 밀레토스(이오니아) → 크로톤(남이탈리아) → 아테네 → 알렉산드리아로 이동.
사상이 지리와 연결되는 경험. CulturalCard 중심.

### 9-3. 과학 혁명 시프트

**예시**: "과학 혁명" (1543 코페르니쿠스 → 1687 뉴턴)

```
페이지 1: 코페르니쿠스 — 지동설 (1543, 프롬보르크)
페이지 2: 튀코 브라헤의 관측 (1576, 벤 섬)
페이지 3: 케플러의 법칙 (1609, 프라하)
페이지 4: 갈릴레이의 망원경 (1610, 파도바)
페이지 5: 갈릴레이 재판 (1633, 로마)
페이지 6: 데카르트의 방법서설 (1637, 레이던)
페이지 7: 뉴턴의 프린키피아 (1687, 케임브리지)
```

### 9-4. 종교 전파 시프트

**예시**: "불교의 전파" (5C BCE 인도 → 6C CE 일본)

```
페이지 1: 싯다르타 — 보드가야의 깨달음 (5C BCE)
페이지 2: 아소카왕의 포교 (3C BCE, 파탈리푸트라)
페이지 3: 실크로드를 따라 서역으로 (1C CE, 간다라)
페이지 4: 중국 전래 — 백마사 (1C CE, 뤄양)
페이지 5: 구마라지바의 번역 사업 (5C CE, 장안)
페이지 6: 한반도 전래 — 고구려·백제·신라 (4-6C CE)
페이지 7: 일본 전래 — 성덕태자 (6C CE, 나라)
```

글로브가 인도에서 시작해서 실크로드를 따라 장안, 한반도, 일본까지.
종교가 수백 년에 걸쳐 대륙을 건너가는 모습을 보여준다.

### 9-5. 경제·교역 시프트

**예시**: "향신료 무역과 대항해시대" (15-17C)

```
페이지 1: 몰루카 제도 — 향신료의 원산지
페이지 2: 베네치아·제노바의 중개 무역 독점
페이지 3: 포르투갈의 도전 — 엔히크 항해왕자
페이지 4: 바스코 다 가마 — 인도 항로 발견 (1498)
페이지 5: 포르투갈의 향신료 독점 (고아, 말라카)
페이지 6: 네덜란드 동인도회사 (VOC, 1602)
페이지 7: 바타비아 건설과 네덜란드 패권
```

### 콘텐츠 유형 확장 가능성

위 예시들은 시작일 뿐이다. 시프트로 만들 수 있는 것:

| 분야 | 예시 |
|------|------|
| **전쟁·정복** | 그리스-페르시아 전쟁, 몽골 원정, 나폴레옹 전쟁 |
| **문화·예술** | 르네상스, 인상파 운동, 할렘 르네상스 |
| **철학·사상** | 그리스 철학, 계몽주의, 실존주의 |
| **과학·기술** | 과학 혁명, 산업혁명, 우주 개발 경쟁 |
| **종교** | 기독교 확산, 이슬람 확장, 종교개혁 |
| **교역·경제** | 실크로드, 대항해시대, 동인도회사 시대 |
| **제국·왕조** | 로마 흥망, 오스만 600년, 청나라 |
| **인물** | 알렉산더, 칭기즈칸, 레오나르도 다 빈치 |
| **장소** | 이스탄불 3000년, 예루살렘, 로마 |
| **사회·법** | 민주주의의 발전, 노예제 폐지 운동 |

각 분야마다 적합한 카드 유형 조합이 다르다.
전쟁 시프트는 BattleCard + PersonCard 중심이고,
철학 시프트는 CulturalCard + PersonCard 중심이며,
교역 시프트는 PlaceCard + GenericCard 중심이다.

## 10장. 콘텐츠 큐레이션 파이프라인 (최종)

### 현재 상태: 임시 폴백

5장에서 정의한 LLM 자동 생성은 **UI 검증용 테스트 데이터**다.
`gpt-5-mini`가 `event_details.description`을 복사하거나 3줄짜리 요약을 생성한 것은
최종 콘텐츠가 아니다.

현재 자동 생성 콘텐츠의 한계:
- 깊이 없음: 사건의 맥락, 원인, 결과를 제대로 설명하지 못함
- 출처 없음: 어디서 온 정보인지 알 수 없음
- 획일적 톤: 모든 사건이 같은 어투로 서술됨
- 오류 가능: LLM 환각 — 사실관계가 틀릴 수 있음

### 최종 파이프라인: 3단계

```
┌──────────────────────────────────────────────────────────┐
│  Stage 1: 소스 수집                                       │
│                                                           │
│  academic_papers 테이블 (이미 수집 시작됨)                │
│  + text_mentions (원전 인용)                               │
│  + event_details.description (기존 설명)                   │
│  + Wikidata 속성 (인물 관계, 날짜 등)                     │
│                                                           │
│  → 각 시프트 페이지에 대응하는 원전/논문 목록 구축         │
└──────────────────────────────────────────────────────────┘
                         ↓
┌──────────────────────────────────────────────────────────┐
│  Stage 2: 큐레이션 초안                                   │
│                                                           │
│  방법 A (이상적): 사람이 소스를 읽고 직접 초안 작성       │
│  방법 B (현실적): LLM이 소스 기반으로 초안 생성           │
│    → gpt-5.1-chat + 소스 컨텍스트 + 프롬프트 가이드라인  │
│    → 프롬프트: "다음 출처들을 참고하여 이 사건을           │
│      이야기체로 서술하라. 반드시 출처에 있는 사실만 쓰라." │
│                                                           │
│  핵심: 5장의 LLM 초안과의 차이는 **소스 기반 생성**       │
│  소스 없이 생성하면 환각. 소스 있으면 팩트체킹 가능.       │
└──────────────────────────────────────────────────────────┘
                         ↓
┌──────────────────────────────────────────────────────────┐
│  Stage 3: 검수 + 다듬기                                   │
│                                                           │
│  사람이 초안 검토:                                        │
│    - 사실 오류 수정                                       │
│    - 톤/스타일 조정 (교과서 X, 이야기 O)                  │
│    - 카드 유형 확인/변경                                   │
│    - 비주얼 자료 추가 (이미지 URL, 지도 등)               │
│    - 출처 연결 확인                                       │
│                                                           │
│  → human_reviewed = true                                  │
│  → quality_score = 수동 평가 (0-1)                        │
│  → status: 'user' → 'featured'                            │
└──────────────────────────────────────────────────────────┘
```

### 소스와의 연결

`academic_papers` 테이블은 이미 수집을 시작했다.
각 시프트 페이지는 관련 소스를 연결할 수 있다:

```
chain_segments.id → (새 조인 테이블) → academic_papers.id
  또는
chain_segments.id → text_mentions (기존) → 원전 인용
```

이를 통해:
- 페이지 하단에 "📚 출처" 섹션 표시
- 사용자가 원전을 직접 확인할 수 있음
- LLM 생성 내러티브의 신뢰도를 소스로 뒷받침
- 추후 `LAPLACE` 시스템의 source attribution과 연결

### 품질 등급

| 등급 | 설명 | 표시 |
|------|------|------|
| **Draft** | LLM 자동 생성, 소스 없음 | 표시하되 "자동 생성" 뱃지 |
| **Sourced** | LLM 생성이지만 소스 기반 | 출처 표시, "AI 작성" 뱃지 |
| **Curated** | 사람 검수 완료 | 뱃지 없음 (기본 상태) |
| **Featured** | 편집자 추천 | ⭐ 뱃지 |

현재 Phase 1의 모든 콘텐츠는 **Draft** 등급이다.
사용자에게 보여줄 수 있지만, "자동 생성된 임시 콘텐츠"임을 명시한다.

## 11장. 글로브 연동 심화

### 상하 분할 뷰 (Phase 1 구현)

기초 기획의 전체화면 모달 대신, **상하 분할**로 구현한다.
위쪽 절반은 글로브, 아래쪽 절반은 시프트 패널.

```
┌──────────────────────────────────────────────┐
│                                               │
│          글로브 (위쪽 ~50%)                    │
│        해당 페이지 위치로 확대                  │
│                                               │
├───────────────────────────────────────────────┤
│  시프트 패널 (아래쪽 ~50%)                     │
│  [← 글로브로] 그리스-페르시아 전쟁 [챕터 ▼]   │
│                                               │
│  ┌─────────────────────────────────────────┐  │
│  │        [ 카드 레이아웃 ]                 │  │
│  │   (8장의 유형별 카드가 여기 렌더링)      │  │
│  └─────────────────────────────────────────┘  │
│                                               │
│  ← 이전  [1][2][3][█][5][6][7]  다음 →       │
└───────────────────────────────────────────────┘
```

**이유**:
- 글로브가 보여야 시프트의 의미가 살아남 (장소 이동 체감)
- 전체화면 모달은 글로브를 완전히 가림 → "글로브 = 인터페이스" 원칙 위반
- 상하 분할이면 페이지 전환 시 글로브 이동이 즉시 보임

**전체화면 모달은 Phase 2 이후 옵션**으로 남겨둠.
읽기에 더 집중하고 싶을 때 "확장" 버튼으로 전환 가능.

### 페이지 전환 시 글로브 애니메이션

```
페이지 3 → 페이지 4:
  1. 글로브가 새 위치로 flyTo (500ms ease-out)
  2. 타임라인 연도 변경
  3. 해당 위치의 마커 하이라이트
  4. 경로 아크에서 현재 구간 강조
```

### 경로 아크와 시프트

시프트가 열리면 글로브 위에 전체 경로 아크가 표시된다.
현재 보고 있는 페이지의 구간만 밝게, 나머지는 반투명.

```
● 마라톤 ──→ ● 테르모필레 ──→ ◉ 살라미스 ──→ ○ 플라타이아
  (완료)        (완료)         (현재)         (미도달)
```

## 부록 B: Phase 로드맵

| Phase | 목표 | 콘텐츠 상태 |
|-------|------|------------|
| **Phase 1** (현재) | 상하분할 UI + 자동시드 + 네비게이션 | Draft (LLM 자동생성, 소스 없음) |
| **Phase 2** | 카드 유형 분화 + 소스 연결 + battle_data | Sourced (소스 기반 LLM 생성) |
| **Phase 3** | 사람 큐레이션 도구 + 품질 등급 | Curated (사람 검수) |
| **Phase 4** | 비전쟁 시프트 대량 생성 (문화/철학/과학) | 혼합 (주요 시프트는 Curated) |
| **Phase 5** | 글로브 경로 아크 + 히어로 카드 + TRISMEGISTUS 연동 | Featured 콘텐츠 중심 |

각 Phase는 독립적으로 의미가 있다.
Phase 1만으로도 "글로브 위에서 사건을 따라가는" 기본 경험이 완성된다.
Phase 2부터 콘텐츠 품질이 올라가고, Phase 4에서 전쟁 이외의 영역으로 확장된다.
