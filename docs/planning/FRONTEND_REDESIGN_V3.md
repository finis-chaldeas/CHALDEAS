**작성일**: 2026-02-20
**최종 수정**: 2026-02-20

## 이 프로젝트가 뭔가

CHALDEAS는 **역사 관측 시스템**이다.

세 개의 축으로 역사를 탐색한다:
1. **공간** (어디서): 글로브를 돌리면서 장소 기반으로 역사를 발견한다.
2. **시간** (언제): 시대별로 훑으면서 시간 흐름을 따라간다.
3. **주제** (무엇을): 과학사, 철학사, 문학사, 군사사 등 분야별로 역사를 읽는다.

이 세 축은 **같은 데이터** 위에서 돌아간다. 사건은 계층(Hierarchy)으로 구조화되어 있고, 사건과 사건은 인물/장소/인과로 연결(Chain)되어 있다. 글로브로 들어오든, 타임라인으로 들어오든, "과학사"로 들어오든 — 결국 같은 이야기에 도달한다.

**한 줄 요약: 공간, 시간, 주제 — 어떤 축으로든 역사의 이야기와 연결을 탐색하는 시스템.**

## 사용자가 뭘 하는 건가

### 경로 A: 탐험자 — "글로브를 돌려본다"

글로브에 관심이 있는 사용자. 지구본을 돌리고 시간을 움직이면서 "이 시기에 여기서 뭐가 있었지?"를 발견한다.

```
1. 글로브를 본다. 시간을 움직인다.
   → "지금 이 시간, 이 장소에서 무슨 일이 일어나고 있지?"

2. 마커를 발견한다. 사이드바에서 맥락을 읽는다.
   → "아, 여기서 페르시아 전쟁이 벌어지고 있구나"

3. 사건을 클릭해서 이야기를 본다.
   → "300명이 테르모필레를 막았구나"

4. 연결을 따라간다.
   → "그 다음에 살라미스 해전이 일어났구나"
   → "레오니다스는 누구지?"

5. 다른 시대/장소로 이동한다.
   → "같은 시기에 중국에선 뭐가 있었지?"
```

### 경로 B: 독자 — "정리된 역사를 읽는다"

글로브에 관심 없는 사용자. 시대별로 훑어보거나, 큐레이션된 이야기를 따라가거나, 특정 인물/사건의 체인을 읽고 싶다. **글로브를 한 번도 안 만져도** 역사를 탐색할 수 있어야 한다.

**시간축으로 읽기 (타임라인):**
```
1. 타임라인을 연다. 시대를 고른다.
   → "고전 시대(500 BCE~500 CE)에 뭐가 있었지?"

2. 시대 안에서 지역별, 주제별로 훑는다.
   → "유럽에선 페르시아 전쟁, 동아시아에선 전국시대..."
   → [주제별 보기] "이 시대의 철학: 소크라테스, 공자, 석가모니"

3. 관심 가는 사건을 클릭한다. 이야기를 읽는다.
   → "페르시아 전쟁이 뭐지? 아, 테르모필레, 살라미스..."

4. 연결을 따라간다.
   → "이 전쟁이 끝나고 아테네 황금기가 왔구나"

5. 다른 시대/주제로 넘어간다.
   → "중세 철학은 어떻게 됐지?"
```

**주제축으로 읽기 (분야별 타임라인):**
```
1. "과학사"를 선택한다.
   → 고대부터 현대까지 과학 발전의 타임라인이 펼쳐진다.

2. 시대별로 주요 과학자와 발견을 훑는다.
   → "고대: 탈레스, 아르키메데스, 에라토스테네스..."
   → "과학혁명: 코페르니쿠스, 갈릴레오, 뉴턴..."

3. 관심 가는 인물/사건을 클릭한다.
   → "갈릴레오의 생애를 따라가보자"

4. 다른 분야로 넘어간다.
   → "같은 시기 문학은 어떻게 발전했지?"
```

**큐레이션으로 읽기 (트리스메기스투스):**
```
1. 트리스메기스투스를 연다. 큐레이션 콘텐츠를 고른다.
   → "가이드 투어: 알렉산더 동방원정"
   → "분야별 이야기: 서양 철학의 역사"

2. 투어/이야기 스텝을 따라간다.
   → "334 BCE 아시아 도하 → 333 BCE 이수스 전투..."
   → "소크라테스 → 플라톤 → 아리스토텔레스 → 헬레니즘..."

3. 스텝에서 관심 가는 사건/인물을 더 파본다.

4. 다른 큐레이션 콘텐츠를 고른다.
```

**세 경로 모두 동일하게 중요하다.** 경로 A는 공간 기반 발견이고, 경로 B는 시간/주제/큐레이션 기반 학습이다. 어느 쪽으로 들어와도 같은 이야기(Event Detail, Hierarchy, Chain)에 도달한다.

## 근본 #1: 이벤트 계층 (Event Hierarchy)

### 왜 이게 근본인가

역사는 트리 구조다. 이게 없으면 28,331개 이벤트는 플랫 리스트이고, 어떤 기능도 의미 있게 작동할 수 없다.

```
제2차 세계대전 (1939-1945)
├ 유럽 전선
│ ├ 노르망디 상륙작전 (1944)
│ │ ├ 오마하 해변 상륙
│ │ └ 유타 해변 상륙
│ ├ 스탈린그라드 전투 (1942-1943)
│ └ ...
├ 태평양 전선
│ ├ 진주만 공격 (1941)
│ ├ 미드웨이 해전 (1942)
│ └ ...
└ ...
```

**이 구조가 모든 곳에서 쓰인다:**
- **글로브**: 줌 레벨에 따라 다른 계층의 사건 표시 (줌아웃=Era, 줌인=Minor)
- **사이드바 관측**: 현재 뷰포트의 사건을 트리로 표시
- **타임라인**: Period 안의 사건을 계층적으로 구조화
- **트리스메기스투스**: 큰 사건의 하위 구조를 내러티브로 풀어냄
- **이벤트 상세**: "이 사건은 X의 일부" + "하위 사건: A, B, C"
- **검색**: 검색 결과에서 상위 사건 맥락 표시

### 현재 상태

- parent_event_id: **0개**. 어떤 이벤트도 부모가 없다.
- hierarchy_level: 전부 3 (Major). 레벨 분류가 안 됨.
- is_aggregate: 전부 false.
- **DB 컬럼은 다 있는데 데이터가 비어있다.**

### 필요한 작업 (P0)

| 작업 | 방법 |
|------|------|
| parent_event_id 구축 | Wikidata P361(part of) + LLM 분류 |
| hierarchy_level 재분류 | 트리 깊이 기반 자동 분류 |
| is_aggregate 식별 | 자식이 있는 이벤트 = aggregate |

## 근본 #2: 역사의 고리 (Historical Chain)

### 왜 이게 근본인가

계층이 "큰 그림 → 세부"라면, 체인은 "앞 → 뒤"다. 사건과 사건이 어떻게 연결되는지.

- **Person Story**: 알렉산더의 생애 — 교육 → 즉위 → 동방원정 → 이수스 → 가우가멜라 → 사망
- **Place Story**: 로마의 역사 — 건국 → 왕정 → 공화정 → 제정 → 멸망
- **Era Story**: 르네상스 — 이탈리아 도시국가 번영 → 예술 후원 → 과학 혁명 → 종교 개혁
- **Causal Chain**: 페르시아 전쟁 → 아테네 전성기 → 펠로폰네소스 전쟁 → 마케도니아 부상

**이 연결이 없으면 "그래서 뭐?"에 답을 못 한다.** 사건을 봐도 "이게 왜 중요한데?", "그 다음엔 뭐가 됐는데?"를 알 수 없다.

**이 구조가 모든 곳에서 쓰인다:**
- **이벤트 상세**: "원인" 섹션 + "결과" 섹션
- **인물 상세**: 생애 타임라인 (Person Story)
- **장소 상세**: 장소 역사 타임라인 (Place Story)
- **타임라인**: 시대의 인과 흐름
- **트리스메기스투스**: 큐레이션된 체인을 독립 콘텐츠로 제공
- **사이드바**: "이 사건의 다음은..." 안내

### 현재 상태

| 체인 유형 | 상태 |
|-----------|------|
| Person Flow (person→events) | `/persons/{id}/flow` API 존재, 20.5%만 연결 |
| Place Story (location→events) | 존재하나 빈약 |
| Era Story | period_narratives 89개 중 7개만 |
| Causal Chain (event_relationships) | **0개** |

### 필요한 작업

| 작업 | 우선순위 |
|------|---------|
| Person-Event 연결 보강 (79.5% 미연결) | P1 |
| Location-Event 연결 보강 (25% 미연결) | P1 |
| event_relationships 인과관계 구축 | P2 |
| period_narratives 생성 (82개 남음) | P1 |

## Part A: 글로브 경험 (경로 A: 탐험자)

### 왜 이 경로가 필요한가

"지구본을 돌려서 역사를 발견한다" — CHALDEAS의 가장 직관적인 경험. 공간과 시간이라는 두 축으로 역사를 탐색한다. 이 경로가 없으면 CHALDEAS는 그냥 역사 위키다.

### A1: 글로브 (세계 상태 디스플레이)

**목적**: "이 시기에 이 지역에서 뭐가 일어나고 있나"를 한눈에 보여준다.

**지금 문제**:
- 마커가 점으로 흩어져 있을 뿐, 시대의 느낌이 안 온다
- 480 BCE 그리스로 가도 "페르시아 전쟁 중"이라는 느낌이 전혀 없다
- 마커 클릭 전에 이미 흥미를 잃는다

**해결**:
- 주요 사건(importance 4-5, hierarchy_level 1-2)은 이름 라벨 + 큰 마커로 눈에 띄게
- 줌인하면 하위 사건이 나타남 (Hierarchy 반영)
- 줌아웃하면 시대 전체의 흐름만 보임
- **핵심: Event Hierarchy가 글로브의 줌 레벨에 매핑되는 것**

**필요한 데이터**: hierarchy_level (현재 전부 3), lat/lng (75% 있음)

### A2: 시간 탐색

**목적**: 시간을 움직이면서 세계가 변하는 걸 본다.

**지금 문제**:
- 타임슬라이더를 움직여도 글로브에 변화가 별로 없다
- "이 시대에 뭐가 중요한지" 맥락이 없다

**해결**:
- 시간 이동 → 글로브 마커 변경 (이미 작동)
- 시간 이동 → 사이드바에 시대 맥락 즉시 표시

**필요한 데이터**: period_narratives (7/89만 있음)

### A3: 관측 사이드바 — "지금 여기서 뭐가 일어나고 있는가"

**목적**: 글로브를 보고 있을 때, "이 시간 이 장소"의 브리핑을 제공한다.

**지금 문제**:
- 사이드바에 탭 10개 (Events, People, Places, Feed, Era, Timeline, Chain, Network, Threads, Servant)
- 뭘 눌러야 하는지 모른다
- Events 탭 = 플랫 리스트. 맥락 없음.

**해결**:
```
┌──────────────────────────────┐
│ Greece · 480 BCE              │
│                               │
│ "페르시아 제국의 2차 침공.     │
│  그리스 도시국가 연합이        │
│  테르모필레에서 저항 중."       │
│                               │
│ Greco-Persian Wars            │
│   ├ Battle of Thermopylae     │
│   ├ Battle of Salamis         │
│   └ Battle of Plataea         │
│                               │
│ Leonidas I · Xerxes I         │
│                               │
│ → 타임라인에서 이 시대 보기    │
│ → 가이드 투어 시작             │
└──────────────────────────────┘
```

사이드바 = **관측 브리핑**. 탭 10개가 아니라, "시대 맥락 + 사건 트리 + 인물 + 다음 액션" 하나.

**필요한 데이터**: period_narratives, parent_event_id, events.category

## Part B: 큐레이션 경험 (경로 B: 독자)

### 왜 이 경로가 필요한가

**글로브에 관심 없는 사용자가 있다.** 이 사람은:
- "중세 시대에 뭐가 있었는지 시대별로 훑어보고 싶다"
- "알렉산더 대왕의 생애를 처음부터 끝까지 따라가고 싶다"
- "로마의 흥망성쇠 이야기를 읽고 싶다"
- "잘 정리된 가이드 투어를 따라가고 싶다"

이 사용자에게 "글로브를 돌려보세요"는 아무 의미가 없다. **타임라인, 트리스메기스투스, 히스토리 체인이 독립적인 진입점**이어야 한다.

글로브 없이도 역사를 탐색하고, 이야기를 읽고, 연결을 따라갈 수 있어야 한다.

### B1: 타임라인 — "시대별로 역사를 훑는다"

**목적**: 시대 → 기간 → 지역 → 사건으로 드릴다운하면서 역사를 체계적으로 탐색한다. **글로브 없이 완결되는 독립 경험.**

**지금 문제**:
- TimelineModal이 "글로브 보다가 여는 모달" 취급이다
- Period에 들어가면 이벤트가 그냥 나열된다
- 89개 Period 중 7개만 AI 내러티브 → 대부분 빈 화면
- 지역별 비교가 안 된다
- 사건을 클릭하면 모달이 닫히고 글로브로 넘어간다 → **독자 경로가 끊긴다**

**해결: 타임라인 = 독립 경험**

타임라인 안에서 모든 게 완결되어야 한다. 사건 클릭이 "모달 닫기 + 글로브 이동"이 아니라, **타임라인 안에서 이벤트 상세가 열리는** 방식.

- events.latitude/longitude (지역별 그룹핑용, 75% 있음)
- persons.domain (분야별 그룹화용, 93.9% 있음 — **바로 사용 가능**)

### B3: 히스토리 체인 브라우저 — "연결을 따라간다"

**목적**: Person Story, Place Story, Causal Chain을 **독립적으로 탐색**한다.

**지금 문제**:
- ChainPanel, NetworkTab, ThreadsTab이 있지만 데이터가 없어서 빈 화면
- Person Flow는 PersonDetailView 안에 있는데, 거기까지 가는 경로가 불편

**해결**:

트리스메기스투스 안에서, 또는 타임라인/이벤트 상세에서 **체인을 시작**할 수 있다.

이벤트 상세 패널에서:
```
┌─── Battle of Thermopylae ──────────────────────────┐
│ ...이벤트 설명...                                    │
│                                                     │
│ ── PART OF ──                                       │
│ Greco-Persian Wars                                  │
│   ├ Battle of Marathon     490 BCE                  │
│   ├ ★ Battle of Thermopylae  480 BCE  ← 지금 여기  │
│   ├ Battle of Salamis      480 BCE                  │
│   └ Battle of Plataea      479 BCE                  │
│                                                     │
│ ── CAUSED BY ──                                     │
│ Persian Empire's expansion → Greek city-states      │
│ resist → First Persian invasion fails →             │
│ Xerxes launches second invasion                     │
│                                                     │
│ ── LED TO ──                                        │
│ Greek victory at Salamis → Persian retreat →        │
│ Athenian Golden Age → Delian League                 │
│                                                     │
│ ── KEY FIGURES ──                                   │
│ Leonidas I (Sparta) → [생애 보기]                   │
│ Xerxes I (Persia)   → [생애 보기]                   │
│                                                     │
│ [글로브에서 보기]                                    │
└─────────────────────────────────────────────────────┘
```

**"PART OF"** = Hierarchy 위로. **"CAUSED BY" / "LED TO"** = Chain 앞뒤. **"생애 보기"** = Person Story. 이 모든 링크가 **현재 뷰 안에서** 다음 콘텐츠를 열어준다. 글로브로 돌아갈 필요 없다.

**필요한 데이터**: parent_event_id (Hierarchy), event_relationships (Chain), person-event 연결

### B4: 주제별 타임라인 — "과학사/철학사/문학사를 쭉 훑는다"

**목적**: 특정 분야의 역사를 고대부터 현대까지 **하나의 연속된 타임라인**으로 읽는다. 시대나 지역에 구애받지 않고, **해당 분야의 흐름**을 따라간다.

**왜 필요한가**:
- "과학은 어떻게 발전해왔지?" — 탈레스부터 아인슈타인까지
- "서양 철학의 역사가 궁금하다" — 소크라테스부터 니체까지
- "세계 문학의 흐름을 보고 싶다" — 호메로스부터 톨스토이까지
- 이런 관심은 시대도 장소도 상관없다. **분야 자체가 탐색의 축**이다.

**지금 문제**:
- 이런 브라우징이 완전히 불가능하다
- persons.domain이 16개 분야로 178,146명 분류되어 있지만, 이 데이터를 활용하는 UI가 전혀 없다
- events.category가 전부 "General"이라 이벤트 자체로는 주제 분류 불가

- "이 시대 보기" → 타임라인 해당 Period로 이동
- "글로브에서 보기" → 글로브 해당 위치로 이동
- 관련 이벤트가 있으면 인라인으로 표시

**분야별 내러티브** (추후):

- 초기엔 없어도 되고, 인물 리스트만으로도 가치가 있다

### C2: 인물 상세 — "이 사람은 누구야"

**목적**: 인물의 이야기. 생애 타임라인(Person Story)이 핵심.

**해결**:
- 인물 기본 정보 (이름, 시대, 분야, 중요도)
- 생애 타임라인 = Person Flow (이벤트들의 시간순 체인)
- 관련 인물 (관계 + 강도)
- 관련 장소
- 출처 (sources)

### C3: 데이터 품질 — 모든 곳에 적용

**목적**: 쓰레기 데이터를 걸러내고, 사용자가 고칠 수 있게 한다.

**해결**:
1. 자동 품질 플래그 (certainty 점수)
2. 시각적 구분 (검증됨/미검증/오류 의심)
3. Report Error 강화
4. 미검증 데이터는 기본 뷰에서 중요도 낮춤 또는 경고 표시

**필요한 데이터**: events.certainty 자동 계산, 날짜 오류 감지, 엔티티 타입 오류 감지

### C4: 검색 — "알고 있는 걸 찾기"

**목적**: 특정 사건/인물/장소를 바로 찾는다.

**지금**: 작동하지만 결과가 섞여 나옴.

**해결**:
- 이벤트/인물/장소 섹션 분리
- 관련도 순 정렬
- 결과 클릭 → 상세 패널 열기 (타임라인/트리스메기스투스 안에서도, 글로브에서도)

**목적**: 신규 유저에게 두 경로를 안내한다.

| 글로브에서 이벤트 클릭 | "타임라인에서 이 시대 보기" → 타임라인으로 |
| 타임라인에서 사건 클릭 | "글로브에서 보기" → 글로브 해당 위치로 이동 |
| 타임라인 Period Detail | [지역별] ↔ [주제별] 뷰 토글 |
| 트리스메기스투스 투어 스텝 | "글로브에서 보기" → 글로브 + 위치 이동 |
| 이벤트 상세에서 인물 클릭 | Person Story가 열림 (경로 B) |
| 이벤트 상세에서 상위 사건 클릭 | Hierarchy 위로 이동 (공유) |
| 인물 상세에서 분야(domain) 클릭 | 해당 분야 주제별 타임라인 (B4)으로 이동 |
| 인물 상세에서 이벤트 클릭 | 이벤트 상세가 열림 (공유) |
| 주제별 타임라인에서 인물 클릭 | Person Story가 열림 |
| 주제별 타임라인에서 시대 헤더 클릭 | 타임라인 해당 Period로 이동 |
| 검색 결과 클릭 | 현재 경로에 맞게 열림 |

**핵심 원칙**: 경로 전환은 **선택적**이다. 독자는 글로브를 안 써도 되고, 탐험자는 타임라인을 안 써도 된다. 하지만 원하면 언제든 넘어갈 수 있다.

## 구현 순서

### 병렬 트랙 A: 데이터 파이프라인 (근본)

없으면 양쪽 경로 모두 빈 껍데기:

| 순서 | 작업 | 이유 |
|------|------|------|
| 1 | **Event Hierarchy 구축** (parent_event_id) | 글로브 줌, 사이드바 트리, 타임라인 구조, 이벤트 상세 전부 의존 |
| 2 | **카테고리 분류** (events.category) | 아이콘, 필터, 주제별 뷰, 주제별 타임라인 |
| 3 | **Period Narratives 전체 생성** (82개) | 사이드바 맥락, 타임라인 Period Detail, 트리스메기스투스 Era Narratives |
| 4 | **쓰레기 데이터 정정** | 신뢰 회복 (양쪽 경로 모두) |
| 5 | **인과관계 구축** (event_relationships) | 이벤트 상세의 "원인/결과", 체인 브라우저 |
| 6 | **인물-이벤트 연결 보강** (79.5% 미연결) | Person Story, 이벤트 상세의 인물 섹션 |
| 7 | **Domain Stories 콘텐츠 생성** | 트리스메기스투스 큐레이션 (과학혁명, 철학사 등) |

### 병렬 트랙 B: 프론트엔드

| 순서 | 작업 | 경로 | 의존 |
|------|------|------|------|
| 1 | **주제별 타임라인 구축** (B4) | 경로 B: 주제 | persons.domain (**바로 가능**) |
| 2 | **타임라인 독립 경험 + 주제별 뷰** (B1) | 경로 B: 시간 | period_narratives, lat/lng, persons.domain |
| 3 | **트리스메기스투스 콘텐츠 허브** (B2) | 경로 B: 큐레이션 | SHEBA episodes, narratives, domain stories |
| 4 | **관측 사이드바 리팩토링** (A3) | 경로 A | period_narratives, parent_event_id |
| 5 | **데이터 품질 표시** (C3) | 공유 | 없음 (프론트 계산) |
| 6 | **이벤트 상세 Hierarchy/Chain** (C1) | 공유 | parent_event_id, event_relationships |
| 7 | **글로브 계층적 마커** (A1) | 경로 A | hierarchy_level |
| 8 | **온보딩 5가지 진입점** (C5) | 공유 | B1, B2, B4 완료 후 |

**B4(주제별 타임라인)가 1순위인 이유**: persons.domain 데이터가 이미 178,146명 분류되어 있어서, **파이프라인 작업 없이 바로 구현 가능**. 즉시 사용자에게 새로운 가치를 제공할 수 있다.

## 검증 체크리스트

### 경로 A (탐험자)
- [ ] 글로브에서 시대별 주요 마커가 눈에 띄는가
- [ ] 줌인/아웃으로 계층적 사건이 나타나는가
- [ ] 사이드바에서 "지금 여기서 뭐가 일어나고 있는지" 즉시 파악되는가
- [ ] 사건 클릭 → 이야기를 읽을 수 있는가
- [ ] 연결을 따라가면 다음 사건/인물로 이동하는가

### 경로 B (독자) — **글로브를 한 번도 안 만지고:**

시간축:
- [ ] 타임라인에서 시대를 고르고, Period로 드릴다운할 수 있는가
- [ ] Period에서 지역별 사건이 구조화되어 보이는가
- [ ] Period에서 주제별 뷰로 전환할 수 있는가 (지역별 ↔ 주제별 토글)
- [ ] 주제별 뷰에서 과학/철학/군사 등 분야별로 사건/인물이 그룹화되는가
- [ ] 사건을 클릭하면 타임라인 안에서 상세가 열리는가 (모달 닫기 X)

주제축:
- [ ] 주제별 타임라인에서 "과학사"를 선택하면 과학자/발견이 시간순으로 나오는가
- [ ] 각 인물에서 Person Story, 이 시대 보기, 글로브에서 보기로 이동 가능한가
- [ ] 다른 분야(철학사, 문학사 등)로 전환할 수 있는가
- [ ] 인물 상세에서 분야 클릭 → 해당 분야 타임라인으로 이동하는가

큐레이션:
- [ ] 트리스메기스투스에서 가이드 투어를 텍스트로 읽을 수 있는가
- [ ] Domain Stories (과학혁명, 서양철학사 등)를 읽을 수 있는가
- [ ] Person Story를 처음부터 끝까지 따라갈 수 있는가
- [ ] Era Narratives를 시대별로 읽을 수 있는가
- [ ] 체인(원인/결과, 상위/하위 사건)을 따라 계속 탐색할 수 있는가

### 경로 전환
- [ ] 타임라인에서 "글로브에서 보기" → 글로브가 해당 위치로 이동하는가
- [ ] 글로브에서 "타임라인에서 이 시대 보기" → 타임라인이 해당 Period로 열리는가
- [ ] 트리스메기스투스 투어 스텝에서 "글로브에서 보기" → 글로브 이동하는가

### 데이터 품질
- [ ] 쓰레기 데이터가 "검증 대기"가 아니라 구체적 오류 표시되는가
- [ ] 오류 신고 버튼이 눈에 잘 보이는가
- [ ] `npx tsc --noEmit` 에러 없음
