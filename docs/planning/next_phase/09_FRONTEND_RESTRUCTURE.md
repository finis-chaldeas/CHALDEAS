# 09. 프론트엔드 구조 개편: 흥미 레벨 / 전문가 레벨

> **작성**: 2026-02-17
> **문제**: 현재 프론트엔드가 재미없다. 정보는 많은데 **경험**이 없다.
> **해결**: 두 가지 UX 레벨로 분리 — 흥미(Interest)와 전문가(Expert)

---

## 1. 현재 문제 진단

### 1.1 유저 경험 흐름 (현재)

```
처음 방문 → 랜딩 (인물 카드 그리드) → "Enter Globe"
→ 지구본 + 좌측 사이드바 (4탭: Feed/People/Timeline/Servants)
→ ??? 뭘 해야 하지?
```

**문제점**:

| # | 문제 | 원인 |
|---|------|------|
| 1 | **첫 화면에서 뭘 해야 할지 모름** | 랜딩이 인물 카드 나열, 액션 유도 없음 |
| 2 | **지구본이 단조로움** | 줌해도 같은 마커, 이벤트 이름만 나열 |
| 3 | **사이드바가 데이터 덤프** | Feed에 중요도순 이벤트 나열 = 교과서 목차 느낌 |
| 4 | **"재밌다" 순간이 없음** | 클릭해도 이벤트 제목+날짜 → 그래서 뭐? |
| 5 | **전문가와 일반인이 같은 UI** | 28,331개 이벤트 목록 = 일반인에겐 무의미 |
| 6 | **네비게이션이 일방향** | 들어간 상세 뷰에서 "다음에 뭘 볼까?" 유도 없음 |
| 7 | **모바일 경험 부재** | 3-column 레이아웃, 모바일에서 사이드바 토글만 |

### 1.2 좋은 참고 사례

| 서비스 | 흥미 유발 방법 | 차용할 점 |
|--------|----------------|-----------|
| **Google Earth Voyager** | 큐레이션 스토리 → 자동 이동 → 설명 카드 | SHEBA 에피소드 자동 투어 |
| **Wikipedia 오늘의 역사** | 하루 5개 이벤트 → 간결한 요약 | 일일 추천 |
| **Civilization VI Civilopedia** | 역사 인물/문명 카드 → 게임 연결 | TRISMEGISTUS |
| **Timelines.ws** | 시각적 타임라인 → 클릭 → 상세 | LAPLACE 개선 |

## 2. 두 가지 경험 레벨

### 2.1 흥미 레벨 (Interest Level)

> **목표**: "5분 안에 역사 재밌네? 하게 만들기"
> **대상**: FGO 오타쿠, 일반 방문자, 처음 온 사람

**원칙**:
- 텍스트 최소화, 비주얼 최대화
- 선택지 3개 이하 (선택 피로 방지)
- "다음 추천"이 항상 보임
- 서번트/에피소드가 낚시바늘
- 지구본 이동이 자동 (유저가 조작할 필요 없음)

**표시 정보**:
- 에피소드 제목 + 한 줄 설명 + 비주얼
- 인물 이름 + 역할 + 서번트 연결
- 이벤트 제목 + 연도 + "왜 중요한가" 한 줄

**숨기는 정보**:
- 좌표, 카테고리 코드, Wikidata ID
- importance 점수, 전체 이벤트 수
- 복잡한 필터/정렬
- 출처 목록

### 2.2 전문가 레벨 (Expert Level)

> **목표**: "깊이 파고들 수 있는 도구 제공"
> **대상**: 역사 관심자, 연구자, 반복 방문자

**원칙**:
- 데이터 밀도 높게 (목록, 필터, 정렬)
- 지구본 = 분석 도구 (줌/패닝/시간축 직접 조작)
- 모든 정보에 출처 표시
- 네트워크/인과관계 시각화

**표시 정보**:
- 전체 이벤트 목록 + 필터 (시대/카테고리/지역/중요도)
- 인물 상세: 생몰년, 출생지, biography, 관련 이벤트, 출처
- 이벤트 상세: 좌표, 참여자, 인과관계, 출처
- 타임라인 분석: 시대별 이벤트 분포, 지역별 비교

### 2.3 전환 메커니즘

```
기본 = 흥미 레벨 (첫 방문자, localStorage에 상태 저장)

전환 트리거:
  1. 사이드바 하단 "Expert Mode" 토글
  2. 상세 뷰에서 "Show more details" 링크
  3. 검색 결과에서 자동 (검색 행위 = 목적의식 있음)
  4. URL 파라미터: ?mode=expert

복귀:
  1. "Simple View" 토글
  2. SHEBA 에피소드 클릭 시 자동 복귀
```

### 3.2 에피소드 투어 모드 (핵심!)

SHEBA 에피소드를 단순 카드가 아니라 **자동 가이드 투어**로 전환:

```
유저가 "테르모필레 전투" 에피소드 선택
→ 지구본이 자동으로 그리스로 이동
→ 480 BCE로 타임라인 이동
→ 하단에 스토리 카드 슬라이드:

┌──────────────────────────────────────────────────┐
│ [지구본: 그리스 확대, 테르모필레 위치 하이라이트]  │
│                                                  │
│ ┌──────────────────────────────────────────────┐ │
│ │ ⚔️ 테르모필레 전투 (480 BCE)                 │ │
│ │                                              │ │
│ │ 300명의 스파르타 전사가 페르시아 대군을 막다   │ │
│ │                                              │ │
│ │ 🎮 관련 서번트: Leonidas I (★★★)            │ │
│ │                                              │ │
│ │ [← 이전]  [관련 인물 보기]  [다음 →]         │ │
│ └──────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

**"다음" 클릭 시**: 같은 에피소드의 다음 이벤트로 자동 이동
(예: 살라미스 해전 → 플라타이아 전투)

**에피소드 종료 시**: "다음 에피소드 추천" 카드

## 5. 구현 방법

### 5.1 모드 상태 관리

```typescript
// settingsStore.ts에 추가
interface SettingsState {
  // ...기존...
  experienceLevel: 'interest' | 'expert'
  setExperienceLevel: (level: 'interest' | 'expert') => void
}
```

localStorage에 영속화. 기본값 `'interest'`.

### 5.2 컴포넌트 분기 전략

**방법 A: 조건부 렌더링** (선택)
```tsx
// FeedTab 내부
if (experienceLevel === 'interest') {
  return <FeedInterest {...props} />
} else {
  return <FeedExpert {...props} />
}
```

**이유**: 두 레벨의 UI가 충분히 다르므로 하나의 컴포넌트에 조건문 넣으면 복잡해짐.
별도 서브컴포넌트로 분리하되, 부모 탭은 공유.

### 5.3 파일 구조 변경

```
frontend/src/components/navigator/

├── FeedTab.tsx                ← experienceLevel 분기
├── FeedInterest.tsx           ← 신규: 흥미 레벨 피드
├── FeedExpert.tsx             ← 신규: 전문가 레벨 피드 (현재 FeedTab 로직 이동)
├── PersonTab.tsx              ← experienceLevel 분기
```

## 8. 핵심 UX 원칙 요약

```
흥미 레벨 = 넷플릭스
  "추천 콘텐츠 → 클릭 → 스토리 감상 → 다음 추천"
  유저가 선택하는 게 아니라, 우리가 보여주는 것

전문가 레벨 = 위키피디아
  "검색 → 필터 → 상세 → 링크 타고 이동"
  유저가 직접 찾고, 우리는 도구를 제공하는 것
```

**가장 중요한 것**: 흥미 레벨에서 **"다음에 뭘 볼까?"가 항상 존재**해야 한다.
에피소드 끝나면 다음 에피소드, 인물 보면 관련 인물, 장소 보면 근처 사건.
**끊김 없는 발견의 연쇄** = 유저가 "역사 재밌네?" 하는 순간.
