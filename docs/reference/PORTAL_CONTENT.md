# Portal Content Guide — 교양 아티클 생성 가이드

## 한 문장

**"현역 중고생이 대학교 교양 수준의 역사를 '오, 이거 재밌다'고 느끼게."**

다큐멘터리를 보는 것처럼 — 놀라운 사실로 시작, 인물의 선택을 따라가고, "이게 왜 지금도 중요한가"로 끝난다.

**핵심 톤**: 똑똑한 친구가 신나서 설명해주는 느낌. 교과서도 아니고 인터넷 밈도 아닌, 재미있고 보기 좋은 잘 쓴 교양 매거진.

## 콘텐츠 원칙

1. **"왜?"로 시작** — "마라톤 전투가 일어났다"(X) → "왜 페르시아는 조그만 그리스를 치러 바다를 건넜을까?"(O)
2. **구체적 디테일** — 숫자, 일화, 인용문 필수. "~라고 한다" 식 뭉뚱그림 금지.
3. **인물 중심 서사** — 사건 나열 X, "이 사람이 이 순간에 무슨 선택을 했는가"
4. **의외의 연결** — "이 전투의 영향은 2500년 뒤 올림픽에까지..." 독자가 "오 진짜?" 할 사실 섹션마다 1개 이상
5. **FGO 연결** — 서번트를 아는 학생에겐 "이 캐릭터의 진짜 이야기"로 진입
6. **3언어** — 한국어 기본 작성, en/ja는 GPT-5.1로 번역

## 아티클 구조 (sections)

### 분량 기준 (실측 검증됨)

- **각 섹션: 1000~2000자 (한국어)**
- **총 6~8 섹션** → 아티클 전체 ~10,000~12,000자
- 읽기 시간 약 15~20분

### 섹션 구조

섹션 이름은 고정이 아니라 주제에 맞게 유동적으로. 아래는 전형적인 흐름:

| # | 역할 | 예시 제목 | 분량 |
|---|------|----------|------|
| 1 | **왜? — 원인과 맥락** | "다리우스는 왜 바다를 건넜는가" | 1000~1500자 |
| 2 | **어디서? — 공간과 조건** | "마라톤이라는 지형이 만든 전장 퍼즐" | 1000~1500자 |
| 3 | **누가? — 인물과 결정** | "장군 10명 중 누가 결정을 내렸나" | 1500~2000자 |
| 4 | **어떻게? — 전개** | "팔랑크스는 느리다? 그날만큼은 달렸다" | 1500~2000자 |
| 5 | **전환점** | "중앙이 밀리고 양익이 이긴다" | 1500~2000자 |
| 6 | **결과 — 숫자와 직후** | "6400 vs 192? — 숫자, 전리품, 그날의 속도전" | 1500~2000자 |
| 7 | **유산 — 이후와 지금** | "전쟁은 끝나지 않았다 — 팔랑크스가 남긴 착각" | 1000~1500자 |

### 섹션 제목 규칙

**제네릭 라벨 금지.** 섹션 제목 자체가 흡인력이 있어야 한다.

- "배경" (X) → "다리우스는 왜 바다를 건넜는가" (O)
- "전개" (X) → "방패와 방패 사이, 1.5km의 돌격" (O)
- "결과" (X) → "192명의 전사자, 그리고 마라톤이라는 이름" (O)

### 톤 가이드

- 구체적 숫자, 일화, 인용문으로 현장감을 살린다.
- 인과관계와 "왜?"를 항상 먼저 설명한다.
- 사람의 선택과 동기에 집중한다. "너라면 어땠을까?"
- 의외의 사실이나 연결점을 자연스럽게 녹인다.
- 문장은 간결하고 리듬감 있게. 장문 나열 금지.
- 단락을 적절히 나눠 읽기 편하게 구성한다.

## 생성 파이프라인: 2단계 에이전트

### 구조

```
Step 1: 아웃라인 (gpt-5.2, reasoning)
  → 전체 구조 설계: 섹션 제목, 핵심 포인트, hook, 분량
  → JSON 출력

Step 2: 섹션별 작성 (gpt-5.2-chat-latest)
  → 각 섹션을 개별 호출로 상세 작성
  → 섹션당 1000~2000자 한국어
```

### 왜 2단계인가?

| 단일 호출 | 2단계 에이전트 |
|-----------|--------------|
| 전체를 한번에 → 뒷부분 품질 저하 | 섹션마다 충분한 토큰 할당 |
| 구조 설계와 글쓰기가 뒤섞임 | Step 1에서 구조 최적화, Step 2에서 글쓰기 집중 |
| 재생성 시 전체 다시 | 부족한 섹션만 재생성 가능 |

### 실측 벤치마크 (마라톤 전투 아티클)

| 항목 | 결과 |
|------|------|
| **총 글자 수** | 11,881자 (7 섹션) |
| **섹션당 평균** | ~1,700자 |
| **총 시간** | 253초 (~4분) |
| **총 비용** | $0.15 |
| **Step 1 (outline)** | 53초, $0.036 |
| **Step 2 (7 sections)** | 200초, $0.115 |

### 비용 예측

| 규모 | 예상 비용 | 예상 시간 |
|------|----------|----------|
| 아티클 1개 | ~$0.15 | ~4분 |
| 컬렉션 1개 (5 아티클) | ~$0.75 | ~20분 |
| 전체 로드맵 (25 아티클) | ~$3.75 | ~100분 |
| + 3언어 번역 | +$2~3 추가 | +60분 |

### 사용법

```bash
cd backend

# 방법 A: 자동 생성 (2단계 에이전트)
python scripts/create_portal_article.py --generate "마라톤 전투" --type history --theme warfare-tactics
# → output/{slug}.yaml 생성
# → 사람이 검수/수정
# → DB에 삽입:
python scripts/create_portal_article.py --import scripts/output/{slug}.yaml
# → 번역 포함:
python scripts/create_portal_article.py --import scripts/output/{slug}.yaml --translate

# 방법 B: 수동 작성
cp scripts/templates/article_template.yaml scripts/output/my-article.yaml
# (YAML 직접 편집 — 한국어로 작성)
python scripts/create_portal_article.py --import scripts/output/my-article.yaml --translate

# 기존 아이템 확인
python scripts/create_portal_article.py --list

# 모델 변경 (Step 1만 영향)
python scripts/create_portal_article.py --generate "주제" --model gpt-5.1-chat-latest
```

### 모델 사용

| 단계 | 모델 | 역할 | 비용 |
|------|------|------|------|
| Step 1: 아웃라인 | `gpt-5.2` (reasoning) | 구조 설계, 핵심 포인트 추출 | ~$0.04 |
| Step 2: 섹션 작성 | `gpt-5.2-chat-latest` | 풍부한 한국어 글쓰기 | ~$0.11 |
| 번역 | `gpt-5.1-chat-latest` | ko→en/ja | 별도 |

### 검수 체크리스트

자동 생성 후 반드시 확인:

- [ ] 팩트 정확성 (날짜, 숫자, 인명)
- [ ] 깨진 문자 없는지 (간혹 non-Korean 문자 혼입)
- [ ] 섹션 간 흐름이 자연스러운지
- [ ] "오 진짜?" 포인트가 섹션마다 있는지
- [ ] slug, year, location이 정확한지
- [ ] related_event_ids를 DB에서 찾아 추가
- [ ] related_servants를 FGO 데이터에서 확인
